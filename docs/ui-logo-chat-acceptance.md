## 当前实现

消息具有独立身份、提交时固定的 normal／deep 模式、公开交付状态和取得的服务端请求编号。状态区分提交、等待、接收、完成、明确失败、未执行与结果未知，不使用进度百分比或私有推理内容。

- 完整回答复制取得原始回复文本，包含 Markdown 与代码，不包含工具卡和按钮文案；已有部分内容也可复制。代码块显示时转义 HTML，代码复制仍独立可用。
- 明确 `accepted: false` 或已知失败／拒绝终态提供「重新发送」。每次重发创建独立消息与请求，固定原模式和传输方式，保留输入框草稿，不重复原来的记忆保存授权；重复点击被阻止。
- 接纳确认不完整、流中断、轮询截止或回执丢失显示「结果未知」。保留部分回复和已取得的编号；有编号可显式查询，无编号明确说明无法查询。不自动再次 POST。
- 「查询结果」仅 GET 原编号，支持仍在执行、终态与回执缺失；查询重复点击被阻止。结束本地等待后仍保留关联，迟到 WebSocket 回执更新原消息。
- 已知终态优先于正在返回的旧查询；未知执行状态优先于表面的失败。旧回执／查询不会结束新消息的二阶或三阶动效，服务端断开流不等于任务取消。
- 流式重绘保留阅读位置和操作焦点；控件暂时禁用或移除时焦点保留在原消息。对话记录不逐 token 播报，独立区域公布状态与终态文本、结果未知提示。

上述消息、草稿和编号关联属于当前页面会话；刷新不恢复聊天历史。没有服务端取消入口，也没有新增后端执行契约。固定预览脚本补齐同源 SSE 编号、可查询的演示回执和明确 404，仍不调用模型或保存长期记忆。
