合计 **11–15 人日**。估算按一名熟悉代码的开发者依次完成、保留原生 JavaScript／CSS 3D 架构、不新增后端管理服务计算。可另留 2–3 人日处理浏览器差异；它不计入上述基础估算。M1 结束后依据实际缺陷修订后续估算，验收未通过不按日历自动进入下一批。

## 3. 可执行工作项

### UL-01：浏览器、下载与离线验收

- 优先级：P0。工作量：1–2 人日。依赖：当前交付包实现。
- 主要位置：`scripts/preview_cube_chat.py`、`ui/web/static/brand-system.js`、`ui/web/static/brand-package.js`、浏览器验收记录。
- 交付：固定测试步骤、设备／浏览器版本、结果记录、下载产物与必要截图；根据发现修复实际兼容问题。
- 首轮支持基线：Windows Chrome 与 Edge 的实际版本；其他浏览器与移动设备按实测列出支持范围，不提前宣称通过。
- 验收：自动保存或保留的手动保存入口至少一条可用；实际落盘 ZIP 可解压、Manifest 对账、PNG 尺寸与透明度正确；分别测试二阶／三阶、不同变体与尺寸。
- 验收：解压后直接打开 `preview.html`，断网运行二阶／三阶合法循环与逆序复原，确认无外部依赖；切换结构、隐藏页面和减少动态效果均正常。
- 验收：组件读取、图片生成或保存失败有明确状态及可用重试；生成期间的配置变化不会改变已捕获的导出参数。

无法执行的浏览器或设备项标为未验证并保留为待办，不用静态检查替代运行证据。

### UL-02：动效异常恢复与生命周期

- 优先级：P0。工作量：2 人日。依赖：UL-01 的浏览器问题清单。
- 主要位置：`ui/web/static/cube-avatar.js`、`ui/web/static/cube-logo.js`、`ui/web/static/cube-animator.js`、`ui/web/static/brand-system.js`。
- 交付：可操作的异常提示、独立静态 Logo 降级、受控重试；改善目前只能刷新重试的错误路径。
- 验收：转动、复原、快速模型切换和对话结束的交叉场景，不产生并行动作、旧回调覆盖新状态或无界监听器／任务增长。
- 验收：重建呈现器沿用可信逻辑状态与已提交动作日志，再执行逆序复原；不得清空日志或直接重置坐标来宣称复原成功。
- 验收：状态无法验证时保持错误状态，静态图层仅承担品牌展示；错误不影响消息输入、接收或资产的标准状态生成。
- 验收：用户暂停与页面隐藏互不解除；减少动态效果后停止循环；标准结束时块身份、位置和朝向完整复原。
- 验证方式：针对已发现的竞态与故障注入增加有效回归，用真实浏览器补足 DOM／动画生命周期验证。

### CHAT-01：对话消息与公开状态体验

- 优先级：P1。工作量：1–2 人日。依赖：M1。
- 主要位置：`ui/web/templates/chat.html`、`ui/web/static/chat.js`、`ui/web/static/i18n.js`、`ui/web/static/cube-chat.css`。
- 交付：完整回答复制；已知失败／拒绝消息的显式重试入口；等待、接收、完成、失败及结果未知的清晰文案。保留已有代码块复制与中文输入法提交保护。
- 验收：复制返回可用文本且不重复包含按钮文案；复制权限失败有反馈；操作可用键盘完成。
- 验收：已接纳但结果未知的请求保留请求标识与查询入口，不自动重复提交；显式重试的新请求有独立身份，并清楚说明模式。
- 验收：每条请求保留提交时的 normal／deep 模式；进行中的二阶／三阶展示不受下一次选择影响；结束后逆序复原。
- 验收：动效只表达活动与公开处理状态，不显示虚构百分比或私有推理内容。

**取消依赖另列**：当前 `app/api_routes/routes_chat.py` 明确规定断开流不会取消已接纳请求。服务端没有完成取消与终态契约前，不交付声称“任务已取消”的按钮。如增加停止本地接收，必须明确服务器可能仍在执行，并保留后续结果查询。真正的任务取消作为独立后端工作项评估，不计入本批工作量。

### DS-01：统一视觉与可访问界面

- 优先级：P1。工作量：2 人日。依赖：M1；与 CHAT-01 的最终控件一起验收。
- 主要位置：`ui/web/static/logo-tokens.js`、共享 UI 样式、`ui/web/static/cube-chat.css`、`ui/web/static/brand-studio.css`、对话与设置模板、`ui/web/static/i18n.js`。
- 交付：界面字号、间距、控件高度、边框、焦点与状态色的统一呈现 Token；几何 Token 继续由现有唯一来源管理。
- 交付：对话区以阅读与输入为主要层级；窄屏中将魔方演示和运动细节折叠为紧凑入口。品牌工作区按预览、配置、资产、交付与规范组织，保持结构稳定。
- 验收：明暗主题与中英文组合；320／390／768／1440px 宽度及 200% 缩放；长消息、代码块、长文件名与错误文案不造成页面横向溢出。
- 验收：Tab、方向键、Home／End、Enter／Space 的现有导航行为保持可用；焦点清晰、无键盘陷阱；静态 aria 标签随语言切换。
- 验收：屏幕阅读器能获知消息与终态；魔方每一步转动不反复播报；颜色不是区分模式和错误的唯一依据。

### THEME-01：全界面统一主题（用户新增范围）

- 优先级：P1。范围：记忆星图、对话空间、品牌与系统设置、记忆列表、旧监控、MVSC 监控、只读提示页。
- 交付：唯一共享呈现 Token、统一浅／深／系统偏好、跨页面同步、画布实时换色和同源微标。
- 验收：主题更换保留星图选择／焦点／相机且不重新请求数据；存储失败不阻断使用；七类页面两种主题在 320／768／1440px 无横向溢出。
- 状态：代码与内置浏览器本地验收已交付；沿用 M2 的原生浏览器、真实缩放和辅助技术综合门槛。详见 [统一主题](ui-theme-system.md)。

### BRAND-01：品牌资产版本与来源追踪

- 优先级：P1。工作量：2 人日。依赖：M2。
- 主要位置：`ui/web/static/logo-tokens.js`、`ui/web/static/brand-package.js`、`scripts/build_brand_assets.cjs`、`scripts/export_brand_kit.cjs`、`docs/brand-system.md`。
- 交付：区分包格式 `formatVersion`、品牌资产版本、Token schema 版本、组件版本；定义兼容与升级规则，增加品牌变更记录。
- 交付：Manifest 记录规范化几何／Token 指纹与组件内容指纹，便于查明资产由哪一版规则生成。继续保留文件字节数与 CRC 损坏检查。
- 验收：同一输入产生相同规范指纹；规则改变后指纹变化；浏览器与 CLI 共用版本定义；预览显示实际包版本。
- 验收：保持现有 SVG／PNG 标准状态和留白规则；生成产物过期时检查失败；无法识别的版本有明确说明。
- 版本规则：比例、间隙、圆角、默认视角或动作契约改变需要明确品牌评审与版本升级；呈现与修复类变更记录兼容影响。版本号与指纹用于追踪，不替代资产使用规范。

### BRAND-02：受控配置导入、预览与撤销

- 优先级：P1。工作量：1–2 人日。依赖：BRAND-01 的版本契约；复用现有本地偏好白名单与迁移能力。
- 主要位置：`ui/web/static/brand-system.js`、`ui/web/templates/settings.html`、`ui/web/static/i18n.js`。
- 交付：导出显示配置 JSON；导入先验证、预览差异，再显式应用；保留上一次有效配置用于撤销。
- 可导入字段仅包含批准的变体、阶数、视角、静态展示、用户减少动态效果偏好与 PNG 尺寸。
- 验收：未知版本、非法值、超出尺寸范围与格式错误不覆盖当前配置；迁移只使用明确支持的版本路径。
- 验收：不导入任意几何、CSS／脚本、魔方动作日志、聊天模式、运行服务参数或凭据；系统减少动态效果偏好仍优先。
- 验收：应用或撤销前完成必要的逆序复原；快速操作只提交最后一次有效选择；本地存储不可用时界面仍可使用并说明未保存。

### PERF-01：实测性能与针对性优化

- 优先级：P1。工作量：1–2 人日。依赖：M3。
- 主要位置：共享动效组件、品牌导出路径、性能测量脚本与记录。
- 交付：固定设备、浏览器、尺寸、减少动态效果设置与操作序列；记录帧间隔分布、长任务、可观测内存／DOM／监听器数量、PNG／ZIP 耗时。
- 测量：二阶与三阶分别连续运行 10 分钟；包含视角切换、隐藏／返回、重复进入工作区与 2048px 导出。以上是拟议测量配置，不是已经取得的性能结果。
- 验收：动作队列、DOM 与监听器不随循环次数增长；停止／隐藏后动画按暂停契约停止推进；重复导出清理临时资源。
- 预算：先记录基线，再按支持设备确定帧与导出耗时阈值；只优化实际瓶颈，保留前后对照，不预先宣称达到 60 FPS。

### REL-01：发布检查与交付说明

- 优先级：P1。工作量：1 人日。依赖：前述工作项验收通过。
- 主要位置：品牌生成／导出脚本、适用的检查入口、`docs/brand-system.md`、`docs/cube-logo.md`、浏览器与性能记录。
- 交付：一套可重复执行的发布检查；版本化交付 ZIP、Manifest、组件 API／接入示例、使用规范、验证矩阵、已知限制与回退说明。
- 验收：适用 JavaScript 回归与 `build_brand_assets.cjs --check` 通过；若改变 API 契约，同步运行对应 Python 测试并更新 API 文档。
- 验收：浏览器包与 CLI 包分别检查目录、参数、版本、文件内容与解压；离线运行证据关联最终包版本。
- 验收：最终浏览器复核覆盖聊天与品牌页，包含 normal／deep、明暗、中英文、减少动态效果、消息失败与导出失败。
- 验收：文档区分实现、实际运行证据和未验证范围；不以测试数量替代性能、视觉或模型效果证据。生产发布另外遵循实际部署流程。

## 4. 每批执行与完成标准
