# EPI-01：可恢复 Episode 记录

EPI-01 为一次事件处理提供可审计的 Episode 契约：事件身份、前后状态引用、
已知的策略/规划版本、动作收据和观察结果可保持在同一条记录中。未取得的信息
保留未知；自动处理记录只覆盖下文明确的范围，不补造工具收据或版本。

## 记录内容

- `event_id`、事件类型、来源、关联 ID
- `state_before` / `state_after` 及完整性哈希
- `policy_version`、`strategy_version`
- 动作 ID、工具 ID、请求哈希、幂等键和回执 ID
- `succeeded`、`failed`、`unknown` 等结果状态及观察向量

Episode 记录动作和回执，不把“事件处理完成”自动当成业务目标完成。
未知外部结果可以保留为 `unknown`，供后续对账。

后续 [ACT-04](action-context-bindings-act04.md) 可将实际 Agent action ID / 请求哈希
关联到上下文/派发意图，并在 metadata 保存该意图 revision 引用。世界/记忆输入
版本由独立引用表达，不把下面 v2 的全量世界快照未知版本改写为已知 revision。

## 存储与恢复

`EpisodeStore` 使用 SQLite WAL，以 `event_id` 和 `episode_id` 双重约束，
支持跨重启读取和幂等追加。`replay_projection()` 只返回状态引用、动作 ID
和结果摘要；它明确标记 `external_actions_replayed=false`，不会重新调用
LLM、工具或外部副作用。

独立 `EpisodeStore` 仍可用于审计契约测试。稳定处理器的可选自动记录使用
`ProcessingEpisodes`，接线和恢复边界如下；线上默认配置仍关闭。

## 处理器自动记录（2026-10-01）

设置 `EVA_ENABLE_PROCESSING_EPISODES=true`，在配置的 `EVA_DB_PATH` 中创建
`episode_processing` 草稿表、`episodes` 封存表、`episode_receipt_outbox` 通知表和
`episode_tool_receipts` 工具收据表。只支持 SQLite，独立于业务
目标开关；legacy 和 Minimal 都通过共享 `EventProcessor` 写入。默认 false，
`/api/runtime` 区分 requested / attached；未启用时不构造记录器或创建草稿表。
当前运行边界仍是单应用实例，不支持多个运行实例共享此数据库并同时恢复。

1. 处理器取得请求执行权后、执行记忆更新和 agent 之前，先持久化处理草稿。
   草稿写入失败阻止本次执行；已排队但未开始、接纳前拒绝的事件不生成 Episode。
2. agent 调用前保存 `started`，返回后保存 `completed` 或 `unknown`。线程内工具
   注册表与 Executor 实际调用另存 `tool_invocation` 和耐久收据，见下文限定范围。
   失败返回不能证明内部外部副作用全部失败；调用结束时间不是外部动作完成证明。
3. 共享 ResultRegistry 的首个终态回执触发封存；后续输出不能升级已封存的未知结果。
   无关联请求 ID 的事件在处理器退出时封存。Episode 写入与目标回执写入分别尝试，
   某一观察者异常不会阻止另一观察者，也不会撤销已经确定的聊天回执。
4. `episodes` 插入、最小终态摘要/通知 outbox 插入与草稿删除在同一 SQLite 事务提交。
   封存失败保留草稿，处理器退出时仅重试审计封存；不重做 agent 调用。内存终态
   的确定早于这次提交，提交失败或提交前骤停仍可能失去内存终态。
5. 启动消费者前，优先读取目标库中已持久化的服务器终态回执，严格核对 task/event
   身份与终态一致性后用于封存；没有可靠回执时将残留草稿封存为 `unknown`，标记
   `recovery_unknown`。没有结束的调用仍为未知，不由成功回执补造工具完成记录。
   此操作在一个事务内完成，损坏草稿或回执使本批恢复回滚并阻止启动。
   重复来源事件 ID 不再次执行；恢复不调用 LLM、工具或外部动作。

自动记录采用 schema v2：`state_before/after.version=null`，实际世界快照经稳定
JSON 编码计算 SHA-256，并标记 `world_snapshot_unversioned`。当前世界模型没有
可靠状态 revision，不能用 0 冒充。只保存哈希，不保存整个快照、模型正文、工具
请求或原始用户消息；未知策略/规划版本为空。并发世界更新可能进入快照，哈希
不能证明一次事件导致了哪些变化。`completed_at` 在此表示记录封存时间，恢复时
不是进程中断前的真实完成时间；图谱明确区分无版本世界快照与 v1 状态 revision。

v1 仍要求非空整数状态版本，现有记录不改写；新读取器支持 v1/v2，旧版本读取器
不能理解 v2。回退代码前应关闭记录开关、正常停止实例并保留数据库；旧读端须
把未知版本视为不可用，不能删除或伪装转换 v2 记录。

草稿只覆盖已开始处理的事件，不是耐久请求接纳、行动 outbox 或完整工具对账。
世界状态、记忆、执行副作用、ResultRegistry 和业务目标在这一封存事务之外；
后续开发仍需状态提交、外部动作对账及未覆盖执行入口的事务/补偿协议。关闭时须先等待真实
worker 结束，再关闭记录连接；构造失败也释放该连接。

## Episode 到目标的耐久通知（2026-10-01）

封存事务在 `episode_receipt_outbox` 保存 v1 终态摘要，仅含 task_id、event_id、
terminal_state、ok；摘要和 Episode 按同一事件关联，task_id 唯一。没有关联请求
的 Episode 不产生通知；不存回复、模型 metadata、工具参数或用户消息。`unknown`
Episode 的摘要 ok=false 表示请求未确认为成功，不是外部动作失败证明。

两个功能都开启时，在消费者启动前完成以下顺序：先构造尚未执行恢复的目标库，
恢复 Episode 草稿并核对已知目标回执，再补送未确认通知，最后执行目标恢复。
已知失败保留失败；成功请求仍须业务验证，重启后遵循现有未完成目标中断策略，
不能因此完成目标。任一步故障阻止消费者启动，并释放构造的连接。

运行中封存后补送，每批最多 32 条，内部上限 128；退出时的审计重试、后续终态
和下一次启动可继续补送。并行补送使用单实例投递锁，外部目标写入期间不持有
Episode 的锁或 SQLite 事务。目标写入成功之后才确认通知；若目标提交后、确认
前骤停，下次重复投递由目标库的同一回执幂等契约处理，不重复推进目标版本。
当前没有独立周期重试线程，持续失败或没有新终态时可能保留积压。

未登记目标的通知由目标 sink 忽略并确认；摘要仍保留。目标功能关闭时通知留待
以后启用；原有封存记录不生成或回填新通知。新增表为增量建表，不删除旧记录。
`/api/runtime` 展示待送数量和本进程投递错误计数，统计不可用时显式标记。

已有目标的显式读取/对账在内存回执缺失时，可以使用同身份的已封存终态摘要。
摘要损坏时返回 503；只读图谱、Episode 引用与历史接口仍不对账。注册新目标
仍要求当前进程已登记的 task_id；`/api/chat/result`、同步响应和 SSE 不从摘要
恢复回复正文，重启后的旧聊天查询仍可能返回 404。

这是 Episode 与目标投影之间的事务 outbox/幂等补偿协议，不是逐工具行动
outbox。通知和 Episode 原子提交，但目标写入是另一个事务；世界、记忆、行动
副作用和内存 ResultRegistry 仍在其外。提交前发生故障且没有持久回执时保留
未知；不宣称无损执行记录或恰好一次外部行动。

## 工具调用耐久收据（2026-10-01）

同一处理记录开关启用后，Orchestrator 在实际执行线程中建立 ContextVar 作用域，
只读取 Core 注入的 causation_id / loop_id。注册工具 `execute_tool()` 和 Executor
通过 `execute()` 到达实际 `_run()` 时记录调用；线程池普通/流式执行都支持。
模型参数、Executor 的任意 task_id 参数不能替换这组身份。调用结束和异常路径
恢复作用域，复用线程不会串入另一个请求。

每次调用使用服务器生成的 action_id、receipt_id，保存父动作、工具 ID、SHA-256
参数哈希、开始时间及已知返回观察。参数经有限 JSON 编码，哈希输入最多 1 MiB；
单 Episode 最多 64 个动作（含 agent），仍受 64 KiB Episode 上限约束，单工具
收据最多 8 KiB。收据表与 Episode 不保存原参数或输出；现有 ExecutorAuditLog
仍是独立的旧审计协议，本改动不改变其参数存储。没有生成外部幂等键。

- 执行前，在同一事务里追加草稿动作和 started 工具收据；写入失败不调用处理器。
- 处理器返回 ok=true，记 completed；返回错误、缺少布尔结果或抛异常则记 unknown。
  这记录处理器的观察，不是远程系统状态认证。finished_at 是实际返回/异常观察时间。
- 返回观察与草稿动作更新原子提交；写入失败向 agent 明确返回 outcome_unknown，
  保留开始记录，不重做当前调用。同一 Episode 中相同工具 ID + 参数哈希有 started
  或 unknown 记录时，重复请求被阻止并标记 previous_outcome_unknown；不同请求或
  不同参数不获得外部幂等保证。
- Episode 首次终态封存或重启恢复时，把尚无返回观察的工具收据标为 seal_unknown，
  finished_at 保持 null。工具未知标记、Episode 封存、终态/outbox 与草稿删除一起
  提交；封存失败全部回滚。已封存 Episode 不接受新工具调用，晚到返回不升级未知
  收据或 Episode。后续需增加独立对账观察，不能拿 late return 直接改写首个终态。

嵌套注册工具 → Executor 是两次入口观察，使用父动作关联，实际处理器仅调用一次；
两个收据不代表两个外部副作用。授权拒绝与边界拒绝没有实际调用收据。Executor
返回 ok=false 现在按 error 记旧审计状态，不再无条件写 success。

目标 Episode 引用/图谱在既有只读快照里读取前 16 个动作所对应的收据，核对行索引、
事件、动作、父动作、哈希、工具及时间；缺失与损坏分别标记，保留已有 Episode 节点。
图谱详情显示工具收据与处理器返回时间，未知封存不冒充完成时间。查看不执行工具、
不补写数据、不推进业务目标。

当前范围不覆盖直接 Agent 文件读取的每个底层系统调用、独立 `/api/tools/call`、
处理器自行创建的新线程或工具内部每次网络重试。进程 worker 仍未开放工具，
没有把 SQLite 连接、ContextVar 或 recorder 放入 IPC。这不是耐久行动派发 outbox，
没有自动对账远程服务或证明外部行动恰好一次。本阶段不启用生产配置。

## 目标证据引用（2026-10-01）

业务目标已接入已有 Episode 的只读引用，沿用 `EVA_ENABLE_BUSINESS_GOALS` 开关。
只查配置的 EVA SQLite 数据库中的 `episodes` 表；独立 `data/episodes.db` 中的
记录不会被隐式合并。只读引用本身不创建、迁移或补写 Episode；处理器记录需要
另行启用上面的开关。尚未封存的草稿不投影；没有记录时界面明确显示“未记录”，
不能由请求成功反推记录存在。

`GET /api/goals/{goal_id}/episode` 在同一个读快照中读取目标来源事件与 Episode，
返回 `read_only=true`，并设置 `Cache-Control: no-store`。状态为 `available`、
`not_recorded` 或 `unavailable`；不存在的目标返回 404，目标功能关闭返回 503。
表不存在与事件未记录分别标注；格式、未知版本、身份冲突、重复事件或读取异常
都标为不可用。只在行索引与记录里的 event_id、episode_id、subject_id 一致、且
event_id 等于目标 source_event_id 时建立引用，不接受客户端提供引用身份。

最多读取 64 KiB UTF-8 原记录，仅投影状态引用、时间、策略/规划版本、结果状态及
动作 ID/回执 ID（最多前 16 个动作）。长版本/回执字段有上限并标注截断；不会
向目标视图投影原始观察、完整 metadata、模型正文或工具请求内容；仅额外投影
经白名单筛选的状态引用种类和封存种类。这些记录本身不是
可信事实认证，也不验证状态哈希的真实性。

目标图谱新增 E 类节点及 `source_event_episode` 引用边；一个 Episode 被多个目标
引用时只绘制一个节点。缺失或异常记录不生成节点，目标详情显示引用状态。查看
不会重放动作、调用文件检查器、补记请求回执、推进过期状态或改变业务成功条件。
Episode 读取失败时仍保留目标投影并明确引用不可用；目标本身读取失败则返回接口
错误。不将缺失误报为执行失败或成功。

这次引用和可选处理器接线均不提供跨组件一致性或无损执行记录保证。
