# RST-01：世界图幂等恢复

状态：实现与回归验证，2026-09-12。对应 [v3 开发计划](source-review-and-roadmap-v3.md) 的 RST-01。

## 修复的行为

旧装配先恢复快照，再从 S4 追加边。相同关系经过反复启动持续重复；S4 查询最多读 5,000 条，快照实体恢复还会将原时间戳改成当前时间。

现在 [WorldModelGraph](../world/world_model.py) 用 `(source, target, relation)` 唯一键保存边，`link` 和恢复都使用相同标识。不同关系、方向和端点不会互相折叠。S4 通过 [WorldModelStore](../memory/tiered_store.py) 的主键游标分页读取全部记录，每页默认 1,000 条；原有面向 API 的 `list_entities/list_edges` 限量接口保持不变。

`load_from_store` 要求适配器提供 `iter_entities/iter_edges`。它在启动、生产者尚未运行时使用；这不是在线多写者恢复协议。所有页面成功读取并解码后才替换内存图，失败时原图保持不变。恢复本身不写 S4，也不会把快照独有记录自动刷进数据库。

## 合并规则

| 情形 | 结果 |
| --- | --- |
| 相同实体 ID / 边三元组，双方有有效且带时区的时间戳 | 保留较新整条记录 |
| 快照与 S4 重叠，时间相同或任一时间缺失、无效、无时区 | 以 S4 为权威回退；不宣称它在时间上更新 |
| 快照内部重复 | 已知时间不同取较新；相同或不可比较取第一条 |
| 只存在于快照 | 保留 |
| 只存在于 S4 | 加入 |
| 内存中有未刷盘修改 | 保留本地修改及 dirty 标记，之后仍可正常 flush |

实体按整条记录选择，不拼接旧属性，避免重新引入新记录已移除的字段。这是现有数据结构下的恢复规则，不是字段级版本、证据合并或分布式因果排序。源系统时钟偏差仍会影响新旧判断。

## 快照兼容

RST-01 引入 `graph_schema_version=1`，并保存边的 `updated_at`；后续 [EVD-01](world-provenance-evd01.md) 将当前写出版本升级为 v2，增加来源。读取支持未版本化旧字典、v1 和 v2；不支持的版本明确报错。旧记录缺少更新时间时保持空字符串，不制造当前时间。原有顶层 focus、mode、last_reply 等字段继续保留。

恢复不调用普通实体创建接口，因而不会伪造创建时间、默认属性或 dirty 写入。输入和导出快照的嵌套 properties 与图内数据分离。

## 验证

[回归测试](../tests/test_world_restore.py) 覆盖：100 次快照/S4 重复恢复、历史重复、时间与权威冲突、快照独有记录、5,101 条数据完整恢复、组合主键分页、读取失败不部分提交、未刷盘修改保留、恢复不写数据库、嵌套数据隔离、版本拒绝及真实装配入口。

[只读样本验证](../artifacts/rst01-snapshot-validation.json) 对已有快照在内存中解码：102,013 条边恢复为 834 个不同三元组，183 个实体保留；全部不同边键保留，之后 5 次往返结果一致。该检查没有写回文件、合并 S4 或迁移运行数据，也不证明相互冲突的历史权重全部被保留。

本批验证结果：新增 18 项回归用例；全量 `python -m pytest -q` 为 **1,163 passed in 115.59s**，`python -m ruff check .` 与 `python scripts/preflight.py` 通过。预检是本地配置/依赖等检查，不代替生产隔离或长期负载验收。

## 上线与剩余工作

当前进程若仍运行旧代码，需要重启后才采用新恢复逻辑。旧进程不会因源文件更新自动改变内存图。

在将新版本用于现有数据前，应备份数据库与快照，并核对重复键中权重冲突的 dry-run 报告。新代码会在读取时规范化重复项，后续正常快照保存会写入规范化图；因此原始历史副本应在首次采用新代码前保存。回退代码时应使用该备份，不能依赖旧恢复逻辑维持幂等。

后续更正：RST-02 检查发现原有启动测试未隔离默认数据路径，RST-01 的全量测试曾保存真实快照；因此此前“历史文件未写回”的说明不准确，只读样本验证本身没有写回。该测试问题和本轮可恢复的数据改动已处理，范围详见 [RST-02 说明](world-recovery-rst02.md)。备份/冲突诊断、恢复副本、有限投影和成本测量现已交付。S4 来源语义修复仍属于 EVD-01。
