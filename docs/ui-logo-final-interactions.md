# UI／Logo 组合交互验收记录

2026-10-01。Windows Codex 内置浏览器，本地预览 `http://127.0.0.1:8779`。本轮补齐组合运行证据，不代表原生 Chrome／Edge、真实模型、屏幕阅读器或生产发布验收通过。

## 组合与结果

| 场景 | 实际结果与证据 |
| --- | --- |
| normal／deep × 明暗 × 中英文 × 系统减少动态效果 | 16 组均取得独立预览回执、完成状态；响应期间使用二阶／三阶；结束后 solved=true、history=0、busy=false，无页面横向溢出。`chat-matrix-16.json` |
| 品牌双阶 × 明暗 × 中英文 × 系统减少动态效果 | 16 组；二阶 8 块、三阶 26 块；系统减少动态效果启用时转动操作禁用，偏好控件由系统接管。`brand-matrix-16.json` |
| 双阶 × 系统减少动态效果 × 六视角 | 24 组；选择与呈现的视角一致，标准状态保持。`brand-views-24.json` |
| 组件读取失败 × 品牌 16 组 | 临时让组件请求返回 503，显示中英文失败说明；忙碌状态解除，保存链接隐藏，下载按钮重新可用。恢复请求后同一导出入口生成 69 文件。`brand-matrix-16.json`、`package-recovery.json` |
| 请求拒绝 × 对话 16 组 | 仅显式提交产生请求，显示未执行及重新发送入口；状态与提示随语言切换，终态公告有内容。`message-failures-16.json` |
| Enter 重发原深度请求 | 下一条选择 normal、原请求仍以 deep 重发；新消息身份和服务端编号独立，remember=false，草稿保留；完成后回到所选二阶标准状态。`retry-recovery.json` |
| PNG 生成失败／恢复 | 让 canvas.toBlob 返回空值，中文／英文均显示明确的重新导出提示，按钮恢复、标准状态保持；移除注入后报告透明 PNG 导出成功。`png-failure-recovery.json` |

证据目录：`artifacts/ui-release/final-interactions-20261001/`。固定回复明确标注预览，不连接模型，也不保存记忆。临时请求与 Canvas 注入均恢复并通过重新加载清除，媒体模拟清除；最终页面为中文、浅色、二阶 Primary、三视角、1024px 和标准状态。

六视角最初一次取样发生在异步模型配置尚未提交时，读到二阶旧结构。保留 `brand-views-24-initial.json`，稳定配置后才取样的重跑文件单独保存，不把中间状态当作最终结构，也不丢弃原记录。一次观察器执行时限导致记录未完整保存，先复核同一页面，再按小批、逐项落盘继续验收，没有重启服务。

## 修复与源码关联

实际失败复核发现 PNG 通用错误提示要求先复原，但当时标识已经是标准状态。`brand-system.js` 的 PNG 路径现在直接显示「PNG 图像生成或保存失败，请重试导出」，同时始终解除 exporting 状态；设置模板脚本缓存版本递增至 10。没有改变几何、合法转动、动作日志、配置或请求协议。

大组合矩阵使用 `local-20261001-theme-roles/report.json` 的源码；`source-verification.json` 核对全部 67 项源码哈希一致。之后仅改 PNG 错误路径和模板脚本缓存版本，再实际验证该路径的中英文失败／恢复。最终检查 `local-20261001-final-interactions/report.json` 的 324 项 JavaScript、34 项 Python、生成资产和三份交付包校验通过；`final-source-verification.json` 保存最终来源及与矩阵基线的差异。没有把旧源码记录追溯成新版本完整运行证明。

生成成功文案与保存链接证明工作区生成流程恢复；本轮没有取得原生浏览器自动保存落盘或离线文件直接执行证据。此前消息查询／结果未知、复制失败和动效恢复的专项记录仍见 [消息验收](ui-logo-chat-acceptance.md) 与 [M1 记录](ui-logo-m1-acceptance.md)。

## 剩余发布门槛

原生 Chrome／Edge 的实际保存与直接离线执行、可靠前台二阶／三阶十分钟性能、真实 200% 缩放和屏幕阅读器仍未验证。完整跨浏览器组合验收还依赖可操作的原生浏览器连接。内置浏览器记录不替代这些门槛，REL-01 与整体验收保持未完成。
