# EVD-01：世界图来源贯通

状态：代码实现与隔离验证，2026-09-12。对应 [v3 计划](source-review-and-roadmap-v3.md) 的 EVD-01；后续任务为 EVT-00。

助手回复中提取的实体、关系现在携带 `assistant_inference`，经过 S4 存储、快照恢复、上下文和查询 API 后保留来源。旧数据缺少来源时为 `unknown`。这是可追踪的来源契约，不是事实验证器。

## 写入与更新

[EventProcessor](../core/event_processor.py) 为回复提取结果附加实际选中的 Agent 和触发事件 ID。提取器返回的“已验证”标签、置信度或来源字段不能覆盖这份运行时来源。自动提取不会因为重复出现就把推断升级成事实。

[WorldModelGraph](../world/world_model.py) 的实体包含 `provenance` 与 `field_provenance`；关系包含 `provenance`。字段来源以 `name`、`properties.<键>` 为索引，描述当前名称及各个顶层属性的来源。嵌套属性整体视为一个值。

更新实体时，仅重写名称和本次提供的属性来源，未涉及的属性保留旧来源。例如助手推断负责人是 Alice，用户随后只更改截止日：负责人仍为助手推断，截止日为用户陈述。不同字段来源不一致时，整条实体为 `unknown`、来源为 `mixed`；不能将整条记录按最高可信等级晋升。

系统补入的任务状态、优先级、创建时间标为 `working_model`、来源 `world_defaults`。这些默认值不冒充用户陈述。属性中名为 `id`、`name`、`provenance` 的普通内容不能遮盖任务导出中的真实标识与来源。

| 标签 | 本批语义 |
| --- | --- |
| `user_statement` | 用户陈述，未自动证明为事实 |
| `assistant_inference` | 助手推断，包括从回复中提取的实体和关系 |
| `tool_observation` | 工具观察；与工具输出的真实性、主张是否被支持是不同问题 |
| `simulation` | 模拟内容；不会因保存、恢复或查询而改成工具观察或事实 |
| `working_model` / `hypothesis` | 工作模型或待检验假设 |
| `unknown` | 无来源、来源格式不支持，或整条实体的字段来源不同 |
| `verified_fact` | 可存储的事实声明标签；本批未实现赋予该标签的事实核验流程 |

Python 内部写入接口的 `origin` 属于调用方契约，不是鉴权边界；错误或恶意的受信调用方仍可提交错误标签。当前回复提取路径强制为推断，没有新增允许 HTTP 客户端自行认定事实的接口。

## 存储、恢复与版本

[迁移 006](../migrations/006_world_entity_provenance.sql) 和 [迁移 007](../migrations/007_world_edge_provenance.sql) 分别为实体、关系增加 `provenance_json`，缺省为 `{}`。旧记录不会被回填成事实，也不改变原内容和时间戳。两次单列迁移支持在实体列已创建、迁移登记尚未完成时重新启动。

来源结构版本为 1；可选 `evidence_ids` 最多保留 16 个不重复字符串，每个最多 160 个字符。它们是引用，不是证据已存在或已核验的保证。未知来源版本降为 `unknown`，不能通过附带字段来源绕过版本检查。

世界图快照写出 `graph_schema_version=2`，读取支持未版本化、v1 和 v2。S4 查询、分页加载和快照恢复均规范化来源。边的 `source` 是起点实体，不能被当作证据来源。

恢复沿用 [RST-01](world-restore-rst01.md) 的整条记录选择规则：有效时间较新者优先，时间相同或不可比较时以 S4 回退。该规则选择保存哪个值，不评价哪个来源更可信；不会汇集所有历史来源。被舍弃的旧冲突值保留在原始备份中。

[恢复工具](../world/recovery_tools.py) 新建 v2 备份包，实体字段来源和关系来源参与内容冲突指纹；只有来源不同的记录也会报告冲突。v1 包继续按其原有序列化及指纹规则校验，可导出原样回滚副本。

本次在 `data/world-recovery/evd01-migration/` 中迁移副本，在 `evd01-v2-bundle/`、`evd01-v2-restore/` 中验证新版备份及恢复。副本保留 **183 个实体、834 条关系**，原 S4 内容及时间戳的摘要前后一致，来源全部为未知，其他快照部分保持一致。见 [迁移回执](../artifacts/evd01-migration-validation.json)。默认运行数据库未迁移；正常启动新版代码时才会对所配置的数据库执行待应用迁移。

## 上下文和界面

`context_projection()` 版本为 2，保留数量和字符串边界、不遍历关系边，并新增来源及 `recent_entity_records`。字段集合仍有限，不复制任意任务属性。投影内整条来源仅聚合该投影实际展示的字段；完整实体的来源可能因此与局部投影不同。

[ContextBuilder](../core/context_builder.py) 与 [LLM 上下文帮助函数](../core/llm_helpers.py) 将记录及字段来源一起编码为 JSON 文本，并标明非指令上下文。来源和事件引用进入提示词前有长度限制。这有助于区分数据与指令，但不构成对模型行为的形式化保证。

`GET /api/memory/world`、S4 浏览、S4 搜索和实体详情返回来源元数据。实体详情改为可序列化的数据类字典。网页浏览和搜索展示“名称来源”，优先使用名称自身的来源，避免混合属性让名称推断身份在界面中丢失。

结构化回复的 `tool_observation` 和 `verified_fact` 都要求引用本轮成功工具回执；`simulation` 保留为模拟声明。回执检查通过仍明确返回 `fact_verified=false`，不宣称工具支持了具体主张。

## 验证与成本

新增 24 个测试用例，覆盖来源枚举、重复恢复、局部更新、默认值、旧库迁移和中断重启、旧快照、格式降级、引用边界、提示词引用、HTTP 查询、提取器伪造来源、仅来源冲突及 v1 包兼容。主要见 [世界图来源测试](../tests/test_world_provenance.py)、[提取路径](../tests/test_event_processor.py)、[恢复工具测试](../tests/test_world_recovery_tools.py) 和 [回复契约测试](../tests/test_evidence_governance.py)。

完整复测：**1,206 passed in 113.79s**，未处理线程异常按失败处理，无警告。实际数据库、快照、profile 和 self-model 四个文件前后 SHA-256 均不变，见 [全量验证](../artifacts/evd01-validation.json)。首次全测为 1,206 通过、1 个调度线程警告，保留在 [首次记录](../artifacts/evd01-validation-first.json)。该关闭测试通过临时一次性任务制造执行中的快照；现已等待 APScheduler 提交完成后再触发关闭，避免任务注册清理与关闭相撞。快照回调仍被阻塞，关闭超时和随后重试的断言保持。此项仅调整测试同步，未宣称修复第三方库的所有关闭竞态。

改动 Python 文件通过 Ruff，网页脚本通过 `node --check`。本批没有进行浏览器视觉验收或真实 LLM 质量评估。

加入来源后重新测量同一快照、30 次内存读取：完整序列化后裁剪中位数 **13.561 ms**、峰值分配 **1,078,168 B**；有限投影 **0.200 ms**、**25,100 B**。见 [成本记录](../artifacts/evd01-projection-current.json)。此次完整序列化也包含来源，不能将这些数值与 RST-02 的旧数据结构当作同等输出比较。测量不包含数据库、模型调用或并发负载，也不是端到端聊天性能结论。
