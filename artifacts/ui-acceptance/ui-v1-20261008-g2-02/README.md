输入变化：每条发送消息限制为 4,000 个 Unicode 字符，与 Pydantic 计数一致；输入框继续保留较长草稿。超限时不清空草稿、不清除“记住这条消息”选项、不生成请求或启动魔方，显示中英文反馈并返回输入焦点。编辑到有效长度后移除错误；重发和直接提交也遵守上限。4000 个 emoji 可提交，不能按 8000 个 UTF-16 单元误拒绝。

新增 5 项有效回归。修复前 [4 项失败](input-before.log)，修复后 [80 项相关客户端测试通过](chat-client.log)；新完整 JS 集合为 480 项。品牌几何、导出组件字节、版本与 API 依赖未改变；聊天样式与脚本缓存参数已更新。

实际 API 注入：在隔离 ChatAgent 的 MockLLM 上使用响应门控，观察 WS／SSE 进行中状态后释放；临时调整容量和待完成期限，验证明确拒绝、已开始任务超时仍不确定、终态不被迟到结果覆盖；最后恢复配置并结束 TestClient 生命周期。受控客户端只回放这些响应，DOM 和动画时序使用测试替身，魔方状态与动作日志采用真实 CubeState／CubeLogo。**不把回放当成原生浏览器实际网络或绘制。**

隔离准备已在本候选 UI 字节上 [复核 18 项](readiness-recheck.log)。后端测试首次运行因测试日志的空设备路径被隔离约束拒绝，见 [准备错误](backend-preparation-error.log)；随后将日志与捕获方式限定到隔离目录再执行。它是测试环境准备问题，不是产品缺陷。

仍待：真实页面输入／焦点／中英文与缩放；真实断流及长回答操作；原生下载、离线、屏幕阅读器、手机软键盘和可靠前台长测。上一轮 Windows URL 识别策略中止记录继续有效，本轮没有再进行原生操作。未调用远端模型或使用生产数据库。
